## What + why
Three clangd changes, each proven first by a spike. 0010: when a compile database
names files through a symbolic link (every project under `/tmp` on macOS), clangd's
background index named a source file one way in its include graph and another way in
its symbols, and threw the source's own symbols away (S13: 3 references instead of
201); it now names the files by their real directory. 0011 and 0012: CLion-style
symbol search, asked for per request (D-113): abbreviated qualifiers (`gi::vert`
finds `GeometryInfo::vertices_per_cell`) and mid-word names (`ector` finds
`TangentVector`), ranked after the usual matches (S14).

## Concepts explained
- **A protocol extension.** clangd reads `workspace/symbol` parameters with a JSON
  mapper that ignores keys it does not know; the patches add two optional keys next
  to clangd's own `limit`, and announce them in the `initialize` reply, so Emacs asks
  only a server that understands them (pyright and texlab ignore unknown keys, but
  get none).
- **A negative score.** The index multiplies a symbol's match score by its quality;
  some fuzzy matches score 0, so a small positive score for mid-word matches still
  outranked them (S14). Mid-word matches score below zero, so they always rank last
  and are the first to go when the reply is cut at its limit.
- **The CommandMangler.** clangd rewrites a compile command's input file to the file
  it asked for; 0010 relies on it (the source is then parsed under its real path).
  The unit test's database does the same, on a real directory with a real symlink:
  an in-memory file system did not reproduce the defect, because clangd's own
  overlay answers real-path questions for the main file.

## Assumptions + risks  (the postmortem ledger)
- **Assumed:** a database answers for the real spelling of a file it lists by a
  linked one (JSON databases do). **Would break if:** a database answered only its
  own spelling; the index would then skip that file, with a log line.
  **DESIGN bet:** D-114.
- **Assumed:** `serverInfo` names clangd "clangd" (it does); a renamed build would go
  without the warning.
- **Risk:** mid-word matches are many (`ector`: 924 on step-1, 95 on the toy with
  the standard library); they come after the usual ones, and `emacs-cpp-symbol-
  middle-match` raises the minimum length or turns them off.
- **Risk:** patches 0011 / 0012 change `ClangdServer::workspaceSymbols`' signature;
  an LLVM update that touches it stops `makepkg` / `build-macos.sh` until rebased.
