> Plain English. The bug and its fix are in the local clangd tree.

## What + why
On RMO, the patched clangd answered the first `M-.` after a restart in 1.4 s instead
of 9.3 s, with the same target. Find-references, though, returned fewer results than
the normal clangd. Comparing the two lists showed why: at the cursor (a call to
`std::visit`), clangd's index records two symbols at exactly the same place; the patch
kept only one, while the normal path asks about both. Now all symbols at that place
count, their references are combined, and each location is listed once. On RMO the
fast answer then contains every location the normal answer has, plus the call under
the cursor, which the normal answer misses. The normal answer also lists several
locations twice; equal counts were therefore the wrong pass criterion, and RUN.md now
compares the sets of locations.

## Concepts explained
- **Two symbols at one place:** a name in the code can stand for more than one
  declaration (here two declarations of `std::visit`); clangd's index then stores one
  reference per declaration, at the same position.
- **Set comparison:** a list of locations can contain repeats; comparing the distinct
  locations is what tells whether something is missing.
