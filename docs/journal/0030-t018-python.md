## What + why
The owner ruled that Python rides along with mode, language server and debugger
(O-19), and installed the three Arch packages. Python buffers now use the tree-sitter
mode, pyright answers navigation and rename through the same eglot keys as clangd,
and dape's ready-made `debugpy` configuration debugs a script.

## Concepts explained
- **Mode remapping:** `major-mode-remap-alist` turns every request for `python-mode`
  into `python-ts-mode`, the variant built on the installed grammar.
- **A Python project:** eglot needs a project root. A git repository is one; a
  directory with `pyproject.toml` or `setup.py` is one too. (Corrected by the code
  review, 0031: this comes from projectile's markers, for every buffer; the
  buffer-local `project-vc-extra-root-markers` this entry described had no effect and
  was removed. Inside a git repository the git root still wins.)
- **Naming the server:** eglot's default list tries pylsp and basedpyright before
  pyright; the explicit entry keeps pyright, and fails loudly if it is missing.
- **Localhost only:** dape's `debugpy` configuration starts the debug adapter with
  `--host 0.0.0.0`, which accepts connections from the whole network; whoever reaches
  the port controls the debugged program. The config replaces it with 127.0.0.1.

## Assumptions + risks  (the postmortem ledger)
- **Assumed:** `python` on the PATH is the system Python that has debugpy (Arch
  python-debugpy). **Would break if:** a virtual environment is active without
  debugpy; dape then says "module debugpy is not installed".
- **Risk:** pyright analyses the whole project on start; large Python trees take a
  while before answers (not measured, no real Python project of the owner's here).
