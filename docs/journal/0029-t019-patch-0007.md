## What + why
S9 run 2 showed patch 0006 working (10 / 10, 0 errors) but the header's decision 1.48 -
1.56 s after opening, over the agreed 1.5 s in half the runs. The wait lasted until
clangd had finished its whole start-up load: reading the stored shards (0.4 s), then
merging their symbols and rebuilding the searchable index (0.6 s). A header needs only
the first part: the list of which source file includes which header is complete as
soon as the shards are read. Patch 0007 ends the wait there. It helps every header
that waits, not only one opened first.

## Concepts explained
- **The load counter:** patch 0005 counts start-up loads that are not finished;
  `includerOf` waits while the count is above 0. The count now goes down right after
  the includers are recorded, inside `loadProject`, instead of after it returns.
